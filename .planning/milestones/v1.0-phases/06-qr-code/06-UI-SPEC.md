# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase ships the `qr-code` island only. Reuse HEAD `src/styles/global.css` tokens (`--bg` `--panel` `--accent` `--danger` `--text` `--muted` `--border`), `.tool-panel` / `.tool-grid.split` / native form controls, and HEAD `ToolShell` (no `locale` prop). ## Spacing Scale

Declared values (must be multiples of 4). Map to existing rem at 16px root:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Quiet-zone inset fallback if canvas already includes modules-only bitmap; checkbox-style gaps unused this phase |
| sm | 8px | Compact gaps (select-to-textarea stack inside the generate controls column; chrome inner gap) |
| md | 16px | Default: `.tool-panel` padding (`1rem`), `.tool-grid` gap, label-to-control gap, generate-block to decode-block gap, populated `.qr-preview` quiet-zone padding |
| lg | 24px | Section break between island and page How-to (existing page `h2` margin — do not change page layout) |
| xl | 32px | Not used inside the island |
| 2xl | 48px | Not used inside the island |
| 3xl | 64px | Not used inside the island |

Exceptions:

- Touch targets stay **44px** min-height on `textarea`, `select`, `button`, and `input[type="file"]`. 44 is not on the 4/8/16 scale; do not shrink below 44px.
- Input / preview border-radius stays **6px** (match HEAD `.md-preview`). Panel radius stays **8px** (HEAD `.tool-panel`). Do not retokenize radius.
- Generate textarea `min-height` is **160px**. QR preview is a **256×256** square (`width: min(256px, 100%); aspect-ratio: 1`) — 256 is a multiple of 4.
- HEAD Copy / Download buttons keep existing horizontal padding; min-height 44px is additive on those controls only, not a `:root` change.

## Layout

**Primary visual anchor:** After the generate textarea has any non-empty text that encodes, the `.qr-preview` surface is the island's focal point (live QR). While generate text is empty, the textarea is the generate anchor. After a successful decode, ToolShell `<pre class="tool-output">` is the decode reading surface. ToolShell output is **not** the QR bitmap.

One page, **two stacked sections**, not tabs. Generate first, decode second. Source/controls first, preview second.

Vertical order **inside** `ToolShell` children, then the existing HEAD error + output + Copy:

1. **Generate section** — Heading role title `generateSection`.
2. **Generate split** — `div.tool-grid.split` with two children, controls first:
   - Left / top: `<label>` + `<textarea>` using `text` copy (`spellcheck={false}`), then `<label>` + native `<select>` using `ecc` copy with options L/M/Q/H, selected **M**.
   - Right / bottom: `<label>` using `preview` copy + `.qr-preview` surface + `<button type="button">` using `downloadPng`.
3. At `min-width: 720px` the generate grid is `1fr 1fr` (existing `.tool-grid.split`). Below 720px the panes stack: **controls then preview**. No extra layout library.
4. **Decode section** — Heading role title `decodeSection`, 16px margin above. Full width. `<label>` + `<input type="file">` using `image` copy.
5. HEAD `ToolShell` error (`role="alert"`) + `<pre class="tool-output">` decoded payload + Copy button.

Do not put the visual QR only inside ToolShell `<pre>`. The `<pre>` is the **copyable decoded text** (QR-05). Generate never assigns a data-URL or canvas dump to `output`.

`.qr-preview` pane chrome (additive CSS only):

- `width: min(256px, 100%); aspect-ratio: 1; height: auto;`
- Idle: `background: var(--bg); border: 1px solid var(--border); border-radius: 6px;` — **empty** (no children, no placeholder node, no dashed empty card, no sample QR).
- Populated: white fill `#ffffff`, 16px quiet zone (padding or encoded quiet zone), black modules `#000000`. Center the 256px square in the split column. `canvas`/`img` `max-width: 100%`.
- Do not set `max-height: 384px` on the QR — the bitmap is a fixed square, not a scrolling document.

Decode does **not** render a thumbnail of the selected file.

## Interaction

- Live generate: `onInput` on the textarea and `onChange` on the ECC select recompute the QR (same live pattern as HEAD `SqlFormatter` / `MarkdownPreview`). No Generate button. No debounce required in the UI contract (engine may hitch at cap; no worker this phase).
- `isTooLarge` runs on generate **text** against `INPUT_MAX_CHARS` (100_000) **before** encode. If over cap: show the text-cap error, clear `.qr-preview`, disable Download PNG, do not run the encoder.
- Empty generate text (`''`) or whitespace-only (`trim() === ''`): idle — skip encode, blank `.qr-preview`, Download PNG disabled. Copy is unaffected (decode payload is independent).
- ECC default **M**. Changing L/M/Q/H re-encodes immediately when text is non-idle.
- PNG download (QR-02): enabled only when a QR is on the canvas. Click builds `canvas.toDataURL('image/png')` (or equivalent blob from the same bitmap) and triggers a temporary `<a download="qr-code.png">`. Filename is always `qr-code.png`. No SVG download (QR-08 deferred). Do not open a new tab as the primary path.
- Canvas internal bitmap is **256×256** CSS pixels including quiet zone. `devicePixelRatio` may multiply the backing store; the downloaded PNG must remain scannable black-on-white.
- Decode: `<input type="file" accept="image/png,image/jpeg,image/webp,image/gif">` only. **Forbidden:** `capture` attribute, `<video>`, `navigator.mediaDevices`, `getUserMedia`, live scan, drag-drop-only with no file input (file input is the required control; drag-drop is out of scope).
- Image byte cap: **5_242_880** bytes (5 MiB), compared to `file.size` **before** `FileReader` / decode. Over cap → image byte-cap error, do not read the file, clear decode payload. This cap is not `INPUT_MAX_CHARS`.
- Unreadable / no-QR / corrupt raster → `No QR code found in this image.` Non-image MIME or failed image decode → `Could not read this file as an image.`
- Decode runs entirely in the browser on the selected file (QR-04). Island must not `fetch` the file to a server.
- Successful decode writes the payload string to ToolShell `output` (Copy enabled). Generate `output` stays unused.
- ToolShell `error` is a single slot: `decodeError ?? generateError`. Clearing the file input (user picks again) replaces decode error/payload. Changing generate text does not clear a successful decode payload.
- Encode failure (data too dense for the selected ECC even under the char cap): encode-fail error, blank preview, Download disabled.
- `spellcheck={false}` on the generate textarea.
- No `aria-live` on `.qr-preview` (would re-announce every keystroke). Associate the Preview label with the surface (`aria-labelledby` or wrapping label). When populated, the canvas/img has `role="img"` and `aria-label` equal to `preview`. When idle, the empty box is presentational (`aria-hidden="true"` on the surface, label still visible).
- Copy remains the existing ToolShell button; disabled when `output` is empty. Download PNG is **not** the Copy button.

## Accessibility

- Every control has a visible `<label>` (Text or URL, Error correction, Preview, Image). Preview label is associated with `.qr-preview` via `aria-labelledby` or wrapping.
- Keyboard: textarea, select, Download PNG, file input, and Copy are in DOM order matching visual order (generate controls → preview/download → decode file → error → output → Copy).
- Focus-visible uses the existing 2px `--accent` outline. Do not remove it.
- Download PNG and Copy `disabled` when their payload is absent (`aria-disabled` not required if native `disabled` is set).
- File input: no `capture`; accessible name is `image` copy. Do not replace it with a click-only fake dropzone that hides the native input from AT.
- Errors go through ToolShell `role="alert"`; do not duplicate the same string as a second live region.
- QR meaning is not color-only: modules are black on white with a quiet zone; accent is never used as the module color.
- Do not auto-play camera/video. Do not request permissions.
- `prefers-reduced-motion`: no QR animation, no layout transition on encode.

## Anti-patterns

- Tabs, segmented controls, or two routes for generate vs decode
- Camera, `getUserMedia`, `capture` attribute, `<video>`, live scan overlay
- SVG download, logo overlay, colored modules, custom eyes
- Placeholder / sample QR when text is empty
- Writing PNG data-URLs or pixel dumps into ToolShell `output`
- A second Copy button, or passing `locale` into HEAD `ToolShell`
- Cloning dirty `JsonFormatter` / `useToolUi`
- Retokenizing `:root` or copying dirty-overlay `--bg-elev` / IBM Plex / Syne into this island
- Showing a thumbnail of the uploaded image
- `innerHTML` / `dangerouslySetInnerHTML` of user text or decoded payload
- Importing QR packages from the island or from any lib other than `src/lib/qr.ts` (CAT-04)
- Rewriting the existing ten tools or their `relatedSlugs` beyond this tool's own row
