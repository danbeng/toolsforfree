# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds a ≤640px accessible hamburger that collapses Tools / Blog / About into an overlay under the header. Work from **HEAD chrome** (Phase 7 ThemeInit / ThemeToggle, `global.css` CSS variables). Do not copy the dirty working-tree overlay (`LangSwitch.astro`, `src/pages/zh/`, IBM Plex / Syne, sticky header). No Tailwind, no shadcn, no icon pack, no new npm packages, no Preact island, no `<details>` / checkbox hack.

Sources: `08-CONTEXT.md` (locked), `07-UI-SPEC.md` (tokens), `REQUIREMENTS.md` NAV-01–05. Discretion used: overlay `--panel` fill + `--border` bottom hairline; `z-index: 20` on `header.site` at ≤640px; 3-line SVG `M5 7h14M5 12h14M5 17h14`; `matchMedia('(max-width: 640px')` `change` listener (not `resize`); dedicated `NavMenu.astro` for the button + `is:inline` script.

Exceptions:

- Do not force 44px min-height on overlay Tools / Blog / About links (three text links; 16px type + 8px vertical padding).

## Copywriting Contract

HEAD chrome labels for Tools / Blog / About stay English. New `ui.ts` keys this phase are **only** `nav.menu` and `nav.close`. Header reads them from an optional `locale` prop defaulting to `'en'`. Do not commit dirty `src/pages/zh/` pages; future ZH pages pass `locale="zh"`.

| Element | Copy |
|---------|------|
| Primary CTA | `Open menu` — `aria-label` on `#navToggle` when collapsed (`aria-expanded="false"`). Verb + noun. Key `nav.menu`. |
| Close label | `Close menu` — `aria-label` on `#navToggle` when open (`aria-expanded="true"`). Verb + noun. Key `nav.close`. |
| Empty state heading | none — nav is a fixed three-link set, never an empty collection. |
| Empty state body | none — do not render “No pages”, a placeholder icon, or a tooltip. |
| Error state | none shown. Menu state is DOM-only (not `localStorage`). Script failures must not toast, inline alert, or `role="alert"`. |
| Destructive confirmation | none — opening or closing the menu is not destructive; no confirm dialog. |

ZH strings (ship in `ui.ts` this phase; not painted until a ZH page passes `locale="zh"`):

| Key | EN | ZH |
|-----|----|----|
| `nav.menu` | Open menu | 打开菜单 |
| `nav.close` | Close menu | 关闭菜单 |

Do not change Tools / Blog / About visible labels or `href`s (`/tools/`, `/blog/`, `/about/`). Do not localize ThemeToggle (`aria-label` stays `Toggle color theme`). Do not add a visually hidden “currently open/closed” string beyond the two `aria-label`s. Do not use `☰`, “Menu”, “导航”, or “Hamburger” as visible or accessible names.

Wire labels: render `aria-label={copy.nav.menu}` plus `data-label-menu` / `data-label-close` on `#navToggle`. The `is:inline` script swaps `aria-label` between those two data attributes; it must not hardcode English.

## UI Considerations

Probe elements: Hamburger `#navToggle` (E1 interactive-control), overlay `#navMenu` / `.nav-links` (E2 nav), ThemeToggle (E3 interactive-control), header bar (E4 nav). Kinds confirmed from UI-SPEC prose (autonomous). 0 unresolved.

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | E1 hamburger, E2 nav, E3 ThemeToggle | ✅ covered | No fetch. Static Astro + `is:inline`; first paint is the closed header. No skeleton or spinner. |
| error | E1 hamburger, E2 nav | ✅ covered | No network. Open/close is DOM class + ARIA only. No `role="alert"` and no error copy (Copywriting Contract). |
| empty | E1, E2 | ✅ covered | Dismissed: empty applies to form / list-collection / media, not this fixed three-link nav. Never render empty-nav chrome. |
| overflow | E2 nav, E4 header | ✅ covered | Overlay is `flex-direction: column` with wrapping links; three items, no inner scroll. Header row does not wrap. |
| long-text | E1 hamburger, E2 nav | ✅ covered | Button has no visible text (`aria-label` only). Tools / Blog / About wrap inside the overlay (`overflow-wrap: anywhere`); no ellipsis. |
| populated | E2 nav | ✅ covered | Dismissed: populated applies to list-collection / media. Happy path is the existing three links, not a data list. |
| partial | E2 nav | ✅ covered | Dismissed: partial applies to form / list-collection. All three links are SSG and always present. |
| zero-one-many | E2 nav | ✅ covered | Dismissed: zero-one-many applies to list-collection. Count is fixed at three. |
| long-text / overflow | E4 header row | 🧪 backstop | At max-width 640px the header stays one row (logo, 44×44 hamburger, 44×44 theme toggle) and the three nav links overlay under the header instead of wrapping the bar |

- Hamburger is a real `<button type="button">` with `aria-expanded` and `aria-controls="navMenu"` matching open state (NAV-02)
- Collapsed overlay uses `inert` **and** `visibility: hidden` so Tools / Blog / About are not keyboard-focusable (NAV-04)
- Escape closes an open menu and returns focus to `#navToggle` (NAV-03)
- Pointer-down outside `header.site` closes the open menu; clicks inside the header (including ThemeToggle) do not
- No body scroll lock and no focus trap — tab may leave the open overlay into `main`
- ThemeToggle stays a sibling **outside** `#navMenu`, always visible at every width; do not put it in the drawer
- Menu state is not persisted; a new page load is always collapsed
- Widening past 640px force-closes (clears `is-open`, `aria-expanded="false"`, restores `nav.menu` label, removes `inert`)
- { statement: "At max-width 640px the header stays one row (logo, 44×44 hamburger, 44×44 theme toggle) and the three nav links overlay under the header instead of wrapping the bar", verification: backstop }

## NavMenu button

New file `src/components/NavMenu.astro`. Static Astro, not Preact, not `client:load`. Contains the button + `is:inline` script only (links stay in `Header.astro` so `#navMenu` remains the collapsible group).

```html
<button
  type="button"
  id="navToggle"
  aria-expanded="false"
  aria-controls="navMenu"
  aria-label={copy.nav.menu}
  data-label-menu={copy.nav.menu}
  data-label-close={copy.nav.close}
>
  <svg class="nav-toggle-icon" viewBox="0 0 24 24" width="20" height="20" aria-hidden="true" focusable="false">
    <path fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" d="M5 7h14M5 12h14M5 17h14"/>
  </svg>
</button>
```

- One 3-line icon, always in the DOM. Do **not** morph to an X. Do **not** use a `☰` glyph or an icon pack.
- SVG is `aria-hidden="true"` `focusable="false"`.
- Two-state open/closed only. No animation library. No `transition` required this phase.

Put visibility / box model **in `global.css`**, not in a scoped component `<style>`:

```css
#navToggle {
  display: none;
  align-items: center;
  justify-content: center;
  width: 44px;
  height: 44px;
  min-width: 44px;
  min-height: 44px;
  padding: 0;
  margin: 0;
  border: 0;
  background: transparent;
  color: var(--text);
  cursor: pointer;
}
#navToggle svg {
  width: 20px;
  height: 20px;
  display: block;
}
```

Do not share a CSS class with `#themeToggle` this phase (do not rewrite ThemeToggle). Duplicate the 44×44 box model.

## Overlay + breakpoint

```css
@media (max-width: 640px) {
  header.site {
    position: relative;
    z-index: 20;
  }
  #navToggle {
    display: inline-flex;
  }
  #themeToggle {
    margin-left: auto;
  }
  .nav-links {
    position: absolute;
    top: 100%;
    left: 0;
    right: 0;
    z-index: 1;
    display: flex;
    flex-direction: column;
    gap: 16px;
    margin-left: 0;
    padding: 16px;
    background: var(--panel);
    border-bottom: 1px solid var(--border);
    visibility: hidden;
  }
  .nav-links a {
    padding: 8px 0;
    overflow-wrap: anywhere;
  }
  .nav.is-open .nav-links {
    visibility: visible;
  }
}
```

Rules:

- Overlay is `position: absolute` under the header. Do **not** push page content. Do **not** use a fullscreen / off-canvas drawer.
- Containing block is `header.site` (`position: relative` at ≤640px only). Panel is full header width (`left: 0; right: 0`), not the `.wrap` column.
- `z-index: 20` on `header.site` at ≤640px so the overlay paints above `main`. Do not make the header sticky (dirty overlay had blur/sticky — skip).
- Fill `var(--panel)`, bottom hairline `1px solid var(--border)`. No top border (header `border-bottom` is the separator). No box-shadow (Phase 10).
- At `min-width: 641px` the hamburger is `display: none` (not in tab order) and `.nav-links` stays the HEAD flex row.
- Do not introduce a second breakpoint. `640px` is `max-width` (NAV-01).

Collapsed (mobile, not `.nav.is-open`): `visibility: hidden` in CSS **and** `inert` on `#navMenu` from JS.

Open: `.nav.is-open` on the `<nav class="wrap nav">`, `visibility: visible`, `inert` removed.

## Script contract

In `NavMenu.astro`, one `<script is:inline>` IIFE. No imports, no `src/lib`, no `localStorage`.

IDs: `#navToggle`, `#navMenu`. Open class: `.nav.is-open` on the `<nav class="nav">` ancestor.

| Event | Behavior |
|-------|----------|
| Click `#navToggle` | Toggle open/closed. |
| `keydown` Escape | If open: close and `navToggle.focus()`. Ignore Escape when closed. |
| `pointerdown` on `document` | If open and the event target is outside `header.site`: close. Do not close when the target is inside the header (logo, hamburger, overlay links, ThemeToggle). |
| `matchMedia('(max-width: 640px)')` `change` | When `matches` becomes false (widen): force-close. Prefer `addEventListener('change', …)` on the MediaQueryList. Do not use a window `resize` listener. |

Close must always:

1. Remove `.is-open` from `nav.nav`
2. Set `aria-expanded="false"`
3. Set `aria-label` to `data-label-menu`
4. Set `inert` on `#navMenu` only when the 640px media query currently matches; **remove** `inert` when wider so desktop links stay operable

Open must always:

1. Add `.is-open`
2. Set `aria-expanded="true"`
3. Set `aria-label` to `data-label-close`
4. Remove `inert`

On first script run: if the 640px query matches and the menu is closed, set `inert` on `#navMenu`. If the query does not match, do not leave `inert` on.

Do not lock `document.body` overflow. Do not install a focus trap. Do not persist open state.

## Interaction contract

| Moment | What the visitor sees |
|--------|------------------------|
| Desktop ≥641px | No hamburger. Tools / Blog / About in one header row, ThemeToggle after About. |
| Mobile ≤640px, closed | One header row: logo, 44×44 hamburger, 44×44 theme toggle. Nav links not visible and not focusable. |
| Click hamburger | Overlay panel (`--panel`) drops under the header with the three links stacked. `aria-expanded="true"`, label `Close menu`. ThemeToggle still in the header row. Page content is covered, not pushed. |
| Click a nav link | Normal navigation; new page loads collapsed. |
| Click ThemeToggle while open | Theme flips; menu stays open (target is inside `header.site`). |
| Pointer-down on `main` | Menu closes. Focus is not moved (pointer close). |
| Escape while open | Menu closes; focus returns to `#navToggle`. |
| Widen past 640px while open | Hamburger hides; overlay row restores; leftover open state cleared. |
| Keyboard, menu closed (mobile) | Tab order: skip link (if any) → logo → hamburger → ThemeToggle → `main`. Overlay links skipped. |
| Keyboard, menu open (mobile) | Tab order: hamburger → Tools → Blog → About → ThemeToggle → `main`. No trap. |
